# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回と同じ gemini-3.5-flash-lite に「AIE2026の講座の宿題にある「3レベル」とは何ですか？」を聞いた。第1回の素の LLM は2回とも「初級、中級、上級のような段階分け」と推測し、2回目は「レベル1は全員必須」という講座の決まりと逆のことまで足していた。エージェントは、基礎（講義内容の確認）、実装（自分でコードを書く）、発展（調査や試行）の3つで、どれか1つに取り組めば完了、原則として採点しない、という用語集の定義どおりに答え、最後に「第1回」と関係する回を添えた。モデルは同じなので、違いを生んだのは用語集を検索するツールと、「答える前に必ず検索する」という指示だと考える。ただ、用語集にない「難易度や目的別に用意された」という言い方が混ざっていて、検索させても言い回しの足し算は残るように見えた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」では、`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2つが、結果が返る前に続けて並んだ。説明文の「query には調べたい用語を1つだけ入れる」に沿って2語に分け、互いの結果を使わないので1回の返事でまとめて頼んだようだ。もっとも、コードを読むと「LoRA」の検索は部分一致で QLoRA も返すので、2回目の検索は結果として重複していたことになる。「第2回の内容から確認問題を1問出して」では `make_quiz({'lecture': 2})` だけが呼ばれ、指示文に「必ず search_glossary で用語集を確認する」とあるのに検索はしなかった。指示文の「必ず」は、プログラムが守らせる決まりではなく、モデルが読んで解釈する文なのだと実感した。
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 「LoRAとQLoRAの違いは？」：requests=2、tool_calls=2（入力 1,196 トークン、出力 177 トークン）
  - 「第2回の内容から確認問題を1問出して」：requests=2、tool_calls=1（入力 949 トークン、出力 53 トークン）

  ツールを2回呼んでも LLM の呼び出しが3回にならなかったのは、2つの呼び出しを1回の返事にまとめたからだ。2回目の呼び出しでは1回目の中身をすべて送り直すので、入力トークンは往復のたびに積み上がる。第1回の app.ask は1問につき1回の呼び出しだったので、ツールを使う質問では、同じ1問でも少なくとも2回分の時間と回数制限を使うことになる。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)` を追加した。指定した回の用語から1つを `random.choice` で選び、「○○の意味は？」という問題と、その定義を答えとして JSON で返す。用語のない回（第0回など）はエラーにせず「第0回の用語は用語集にありません。用語がある回: 1, 2, 3, 4, 6」と返すようにし、テストがダミーの `lecture=0` で呼んでも落ちないようにした。docstring は「指定した回の用語から1つを選び、確認問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。lecture には回の番号を整数で入れる（例: 第2回なら 2）。」とした。`--list-tools` に3つ目のツールとして現れ、`--trace` では `lecture=2` で呼ばれ、`pytest` は15件すべて通った。意外だったのは、ツールは答えも返したのに、エージェントが問題だけを出して答えを伏せたことだ。この CLI は1回で終わって会話を引き継がないので、「答えは？」と続けて聞いても前の問題を覚えていない。確認問題のように往復が続く使い方には、前の会話を渡す仕組みが要りそうだ。コードは Claude Code に書かせ、差分を読んで採用した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：説明文（docstring）と INSTRUCTIONS を一度に1か所だけ書き換え、同じ質問を書き換えの前後で2回ずつ `--trace` 付きで打って比べた。実験Aでは、`search_glossary` の docstring の「query には調べたい用語を1つだけ入れる（例: "LoRA"）」を「関係する用語をまとめて1回で入れる（例: "LoRA QLoRA"）」に変え、「LoRAとQLoRAの違いは？」を聞いた。実験Bでは、INSTRUCTIONS から「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する」の1行を消し、「AIE2026の講座の宿題にある「3レベル」とは何ですか？」を聞いた。消しても検索が続いたので、講座に固有の質問だからモデルが自分で検索を選んだのかを確かめるため、一般的な用語の「LoRAとは何ですか？」も足した。書き換えと戻しは Claude Code に行わせ、実験のたびにコードを元に戻して差分が無いことを確かめた。
- 結果：
  - 実験A（前）：`search_glossary('LoRA')` と `search_glossary('QLoRA')` の2回、requests=2、入力 1,386 トークン（2回とも同じ）
  - 実験A（後）：`search_glossary('LoRA QLoRA')` の1回、requests=2、入力 1,087 トークン（2回とも同じ）
  - 実験B「3レベル」：前も後も `search_glossary('3レベル')` の1回、requests=2、入力は 973 から 925 へ
  - 実験B「LoRA」：前も後も `search_glossary('LoRA')` の1回、requests=2、入力は 1,131 から 1,083 へ

  回答の中身は、どの条件でも用語集の定義に沿っていた。
- 気づき・疑問：docstring の1文を変えるだけで呼び方ははっきり変わったのに、INSTRUCTIONS の「必ず」の1行は、消した後の4回でもすべて検索が続いた。演習では逆に、「必ず」があっても確認問題の質問では検索しなかったので、この1行は、少なくとも今回の質問では、検索するかどうかを決めていなかったことになる。検索が続いたのは、docstring に「AIエンジニアリングの用語や、この講座に固有の言葉について答える前に使うこと」とあるためか、INSTRUCTIONS の「回答の最後に、関係する回を示す」に答えるには用語集の回の番号が要るためか（あるいは両方）だと考えているが、docstring の文も消して確かめるところまではしていない。意外だったのは、検索をまとめても LLM の往復が2回のまま減らなかったことで、2つの検索はもともと1回の返事でまとめて頼まれていた。減ったのは送り直す検索結果の量で、入力は約2割減った。ただ、まとめた検索が正しく当たったのは `search_glossary` が部分一致で作られているからで、docstring はツールの実際の作りと合わせて書かないと、呼び方だけが変わって答えが悪くなりうると感じた。また、make_quiz を登録しただけで、使わない質問でも入力が1回あたり約95トークン増えたように見え、INSTRUCTIONS の1行を消すと約24トークン減った。ツールの説明や指示は、使うかどうかに関係なく毎回の送信に乗るので、増やすほど1回あたりの費用がかさむ。
